# Cross-Browser Specification

**Status:** Draft v0.1 (2026-11-15) | **Tickets:** Phase 0 Sprint 1, Phase 5
**Sources:** `ref-docs/chrome-mv3.md`, `ref-docs/firefox-mv3.md`, `ref-docs/cross-browser-differences.md`,
`ref-docs/research-report.md` §4

One codebase and one `wxt.config.ts` produce both packages. Browser differences live **only** in the
manifest function in `wxt.config.ts` and, if ever needed, behind `import.meta.env.BROWSER` checks in a
single module (`src/platform.ts`). Feature code never branches on the browser.

## 1. Targets

| Browser                  | Manifest  | Background                                                       | Minimum version | Build command                                                          |
| ------------------------ | --------- | ---------------------------------------------------------------- | --------------- | ---------------------------------------------------------------------- |
| Chrome / Chromium / Edge | MV3       | `service_worker` (generated by WXT)                              | Chrome 121      | `pnpm build`                                                           |
| Firefox desktop          | MV3       | `scripts` (event page; Firefox has no service worker background) | Firefox 142     | `pnpm build:firefox` (MV3 via `manifestVersion: 3` in `wxt.config.ts`) |
| Firefox for Android      | not in v1 | --                                                               | --              | --                                                                     |

Why these floors:

- **Firefox 142.** AMO requires `data_collection_permissions` for new add-ons. Desktop Firefox honours
  the key from 140, but Firefox for Android only from 142, and `strict_min_version` applies to both.
  `web-ext lint --warnings-as-errors` fails with `KEY_FIREFOX_ANDROID_UNSUPPORTED_BY_MIN_VERSION` at
  140, as verified on the Phase 0 skeleton on 2026-11-15. Versions older than 140 are reported to
  reject the key.
- **Chrome 121** gives the MV3 behaviour this project needs. Raising the floor to 148 would allow the
  native `browser` namespace and promise-returning `onMessage`, but nothing requires that.

WXT builds Firefox as MV2 unless told otherwise. `manifestVersion: 3` in `wxt.config.ts` applies MV3
to every command, so no script needs `--mv3`. Sources: `ref-docs/firefox-mv3.md`,
`ref-docs/wxt-framework.md`.

## 2. Generated manifest

### 2.1 Baseline (what `wxt.config.ts` produces today)

Shared keys, as built today (WXT adds `version` from `package.json`, `icons` discovered from
`public/icon/*.png`, and the `background` entry):

```json
{
  "manifest_version": 3,
  "name": "GH ListRollup",
  "description": "Collapse GitHub's repository file listing to one line and expand folders inline as a nested tree.",
  "homepage_url": "https://github.com/doublegate/GH-ListRollup",
  "host_permissions": ["https://github.com/*"],
  "icons": {
    "16": "icon/16.png",
    "32": "icon/32.png",
    "48": "icon/48.png",
    "96": "icon/96.png",
    "128": "icon/128.png"
  },
  "content_scripts": [
    {
      "matches": ["https://github.com/*"],
      "js": ["content-scripts/content.js"],
      "css": ["content-scripts/content.css"],
      "run_at": "document_start"
    }
  ]
}
```

Firefox adds:

```json
{
  "browser_specific_settings": {
    "gecko": {
      "id": "gh-listrollup@lparobek.dev",
      "strict_min_version": "142.0",
      "data_collection_permissions": { "required": ["none"] }
    }
  }
}
```

Chrome adds `"minimum_chrome_version": "121"`.

### 2.2 Additions by later tickets

| Addition                                                         | Ticket    | Condition                                                                                       |
| ---------------------------------------------------------------- | --------- | ----------------------------------------------------------------------------------------------- |
| `"permissions": ["storage"]`                                     | T-GNR-301 | Added when Phase 3 settings land (omitted in v0.1.0 so stores do not flag an unused permission) |
| `"options_ui": { "page": "options.html", "open_in_tab": false }` | T-GNR-303 | Always; WXT adds it once `src/entrypoints/options/` exists                                      |
| `"https://api.github.com/*"` in `host_permissions`               | T-GNR-302 | Only if ADR 0003 keeps the REST fallback (T-GNR-209)                                            |

Each ticket updates §2.1 when it lands, so §2.1 always describes the current build.

Rules for the manifest:

- **Content script scope.** The content script matches all of `github.com`, because GitHub navigates
  in-app. A script matched only to code pages would never load when the user reaches a code page from
  an issue page without a full reload. The page detector decides whether to act (`docs/architecture.md`
  §2).
- **Permissions not requested:** `scripting`, `tabs`, `activeTab`, `webRequest`, `<all_urls>`, and
  `optional_host_permissions`. GitHub Enterprise Server support would add the last of these later.
- **The `api.github.com` host permission** exists only for the token fallback. The Phase 0 skeleton
  ships without it; ticket T-GNR-302 adds it together with the fallback. If Phase 2 shows the
  same-origin source is enough, remove the permission and the fallback (`docs/adr/0002`).

## 3. Runtime differences that matter

| Topic                        | Chrome                                 | Firefox                                      | Project rule                                                                                                                                                                    |
| ---------------------------- | -------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API namespace                | `chrome.*` (also `browser.*` from 148) | `browser.*`                                  | Use WXT's `browser` import everywhere, never `chrome`.                                                                                                                          |
| `onMessage` reply            | promise return needs 148+              | promise return supported                     | Always use `sendResponse` + `return true` until the Chrome floor is 148.                                                                                                        |
| Host permission grant        | at install; the user can withhold it   | at install from 127+; the user can revoke it | Check with `permissions.contains()` at startup. If access is missing, the options page shows a "Grant access" button that calls `permissions.request()` from the click handler. |
| Content-script `fetch`       | page CORS rules                        | page CORS rules                              | Only same-origin `github.com` fetches run in the content script. `api.github.com` fetches run in the background.                                                                |
| `storage.local` access level | `setAccessLevel` available (140+)      | not available                                | The token is never passed to the content script, so access level does not matter.                                                                                               |
| `storage.sync`               | syncs                                  | syncs on desktop; not on Android             | Sync is best-effort; nothing depends on it.                                                                                                                                     |

## 4. Verification per browser

- Run `pnpm build` and `pnpm build:firefox`. Check the generated `manifest.json` in each build against
  the §2.1 baseline plus the §2.2 additions that have landed. Today this is a manual check; a
  planned `pnpm check:manifest` test (not yet in `package.json`) will load both manifests and assert
  the keys.
- Run `web-ext lint --source-dir .output/firefox-mv3 --warnings-as-errors` with zero findings.
- Load both builds unpacked and run the manual smoke checklist in `docs/testing-strategy.md` §5.
